# AxieOS Engineering Log

## New Pouch / VRF Data Model

Added:

```text
pouch_opening_events
pouch_reward_items
```

The new schema supports tracking:

- pouch type
- quantity opened
- Fortune Slips spent
- VRF request transaction
- VRF fulfillment transaction
- upfront RON
- user transaction fee
- VRF refund
- net RON cost
- individual pouch rewards

This provides the foundation for future VRF batch-cost and pouch-efficiency analytics.

---

# New Pouch Data Entry Tool

Created:

```text
scripts/add_pouch_opening_event.py
```

The tool supports creating a pouch-opening event and its rewards.

Reward entries use:

```text
ITEM:QUANTITY
```

Example:

```powershell
--reward "Regular Choco:2"
--reward "Premium Choco:1"
```

The parser and database insertion logic were tested successfully using an in-memory SQLite database.

# Marketplace Reporting Improvements

Previously, open marketplace positions only supported Axies using unique `asset_id` values.

The report was extended to support fungible marketplace items such as:

```text
Premium Choco
```

Consumables can now be matched using:

```text
daily session
+ asset type
+ asset name
+ quantity
```

while Axies continue to use their unique asset IDs.

This allows the report to display both:

```text
Beast Axie #7087631
```

and:

```text
Premium Choco ×3
```

as open marketplace capital positions.

---

# Inventory Model Improvements

Pouch rewards are now treated as authoritative inventory inflows through:

```text
pouch_reward_items
```

The inventory summary combines:

```text
inventory_events
+
pouch_reward_items
```

This avoids manually entering the same pouch reward twice.

Historical Premium Choco inventory was also reconciled so the August 9 usable balance now reflects the carry-forward balance correctly.

## Renewable Resource Strategy

Fortune Slips were used not only for Bounty rerolls but also to increase consumable reserves.

Current resource distinction:

```text
ETH            = scarce operating capital
Fortune Slips  = renewable daily resource
RON            = blockchain operating resource

Axies          = recoverable marketplace capital
```

This distinction should become part of the eventual Bounty optimization engine.
