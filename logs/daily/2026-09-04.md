# 3. Why the Migration Was Required

Historical Terrarium records include some dates where:

```text id="xvcnrw"
Terrarium metrics = observed
```

but:

```text id="a444cu"
Fortune Slip buff state = unknown
```

The old schema effectively required:

```text id="re0me1"
buff_active = true
or
buff_active = false
```

This forced an interpretation that the historical evidence did not necessarily support.

The new model allows:

```text id="578eco"
true
false
unknown
```

which better preserves source provenance.

---

# 4. New buff_active Semantics

Canonical interpretation:

| Database Value | Meaning                              |
| -------------- | ------------------------------------ |
| `1`            | Buff explicitly observed active      |
| `0`            | Buff explicitly observed inactive    |
| `NULL`         | Buff state not established by source |

The important new case is:

```text id="lpjuz9"
NULL
=
UNKNOWN
```

not:

```text id="t5p6za"
NULL
=
inactive
```

---

# 5. Data Integrity Principle

September 4 formalized an important AxieOS rule:

```text id="u2ff02"
unknown
≠
false
```

For historical reconstruction:

```text id="1tgajd"
absence of evidence for buff
≠
evidence that buff was inactive
```

Therefore incomplete historical metadata should remain explicitly unknown.

# 10. Historical Backfill Architecture

The improved recovery flow is now:

```text id="8i5crk"
historical source
        ↓

        ↓

        ↓
active / inactive / unknown
        ↓

```

Rather than:

```text id="rwf9zr"
historical source
        ↓

        ↓
insert
```

# 11. Three-State Evidence Model

The migration establishes a broader pattern useful elsewhere in AxieOS.

For historical data:

```text id="u2fasc"
OBSERVED TRUE
OBSERVED FALSE
UNKNOWN
```

should remain distinguishable.

This is useful for:

* Terrarium buff state
* ownership provenance
* marketplace disposition
* bounty completion evidence
* transaction-purpose classification
* historical inventory state

---

# 12. Canonical vs Evidence Data

V0.11 increasingly distinguishes:

## Canonical Snapshot

A sufficiently complete observation that satisfies the main Terrarium data model.

## Partial Evidence

A source containing some useful metrics but not a complete canonical state.

The nullable `buff_active` migration allows canonical rows to preserve uncertainty in one field without inventing values.

This is different from allowing completely incomplete observations into the canonical table.
