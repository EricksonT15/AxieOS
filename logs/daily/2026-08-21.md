# 18. Incremental Sync Model

The intended workflow is:

```text
existing canonical transaction store
        ↓
query Ronin Explorer API
        ↓
identify newest previously recorded transaction
        ↓
fetch only unseen blockchain records
        ↓
normalize
        ↓
deduplicate
        ↓
append
```

The key requirement is:

```text
same blockchain transaction
→ processed once
```

This protects against duplicated accounting when the sync script is run repeatedly.

# 22. Source-of-Truth Architecture

AxieOS should preserve three distinct layers.

## Layer 1 — Raw Blockchain Evidence

```text
Ronin Explorer API JSON
```

Never modify.

---

## Layer 2 — Normalized Blockchain Events

```text
canonical transaction/event records
```

Responsibilities:

* normalize addresses
* timestamps
* asset amounts
* methods
* transaction hashes
* wallet direction
* gas
* event identity

---

## Layer 3 — Accounting Events

```text
economic interpretation
```

Examples:

* NFT purchase
* NFT sale
* Bounty reward
* Terrarium reward
* Staking action
* Consumable acquisition
* Internal transfer
* Gas expense

This separation prevents future interpretation changes from corrupting the underlying blockchain data.
